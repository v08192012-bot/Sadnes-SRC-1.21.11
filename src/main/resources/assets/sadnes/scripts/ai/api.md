# sadnes scripting API

Script structure: a folder with `src/main.js` (entry point; `include("file.js")` attaches more files from src/) and `assets/` (any files). Header meta in the first comment lines: `// @name`, `// @author`, `// @version`, `// @description`. Modules are declared with `Module("Name")` and show up in the GUI scripts page.

Custom shaders: `render3d.shader("name.fsh")` compiles `assets/name.fsh`, `handle.draw(x, y, z, size[, color, p0..p3])` renders a camera-facing quad. The fragment gets `in vec2 uv` (0..1), `in vec4 vertexColor` and UBO `layout(std140) uniform SadnesScriptFx { float uTime; float uSize; float uP0; float uP1; float uP2; float uP3; float uPad0; float uPad1; }`. Blend is additive without depth write — output premultiplied: `fragColor = vec4(color * alpha, alpha)`.

Aura hooks: `aura.rotation("Name", fn)` / `aura.esp("Name", fn)` add a custom mode to the client's aura rotation list / Target ESP style list while the script is enabled. The rotation fn gets `{target, yaw, pitch, distance, range, cooldown}` and returns `{yaw, pitch, yawSpeed, pitchSpeed, returnSpeed}`; the esp fn gets `{target, color, alpha, partial, x, y, z, width, height}` and draws with `render3d.*`.

Watermark chips: `watermark.chip("Name", {icon, value, unit, badness, enabled})` adds a chip to the client's Watermark HUD (it shows up in the Items list and can be dragged like built-in ones). `icon` is a client icon name (see the list below) or `"file.svg"` from the script's assets; `value`/`unit` are a string or a function returning one (called every frame); `badness` is a function returning 0..1 that tints the chip with the Watermark's "bad value" color. The handle has `name, icon(name), value(v), unit(v), badness(fn), remove()`. Chips exist only while the script is enabled and are removed on reload/unload.

ESP: `esp.element("Name", {size, render, replaces, categories, anchor, icon, enabled})` adds your own element to the client's ESP — it shows up in the ESP preview's element list (right click) next to Nametag/Box, is toggled and dragged like built-in ones, and its state is saved with the script. `size` is `{w, h}` or a function `(e) → {w, h}` (return null to skip that entity); `render(e)` draws with `render.*` at `e.x, e.y, e.w, e.h`. The callback argument `e` has `entity` (entity handle), `category`, `preview` (true in the ESP preview), `alpha` (already applied to `render.*` colors) and `box {x, y, w, h}` — the entity's screen box; in the `item` category it also has `items` — the item handles of the whole pile on that block (dropped items of one block share one tag, the rest of the pile is skipped). `categories` is an array of `esp.categories()` names (`friends, naked, invisible, others, self, animal, mob, item`) or `"players"`, default all; `anchor` is the start position around the box (`top, bottom, left, right, center, top_left, top_right, bottom_left, bottom_right`); `icon` is a client icon name for the list row. `replaces: "nametag"` (any built-in element name: nametag, box, glow, chams, healthbar, potions, armor, held_items, cooldowns) puts your element in place of the built-in one instead of on top of it: while the script is enabled the built-in is switched off in those categories, your element takes its row in the list, elements attached to it follow yours, and a nametag replacement hides the vanilla name like the built-in does. The handle has `name`, the setting factories (`checkbox, slider, mode, multi, color…` — they appear in the element's gear panel) and `remove()`.
ESP shaders: `esp.chams("Name", {shader, color, params, model, replaces, categories, icon, enabled})` and `esp.glow("Name", {shader, radius, color, params, replaces, categories, icon, enabled})` add ESP elements drawn with your own fragment shader from `assets/` (`shader: "lava.fsh"`). They sit in the ESP preview's element list like `esp.element` (toggle, gear panel with the handle's setting factories, `replaces: "chams"`/`"glow"` to take the built-in's place; without `replaces` they are drawn on top of it) and are rendered only in the world. `color` is the tint (number or `(e) → number`, default the client accent), `params` is `[p0, p1, p2, p3]` or `(e) → [...]` — both are read once per frame, `e` is `{category}`. Both kinds get UBO `layout(std140) uniform SadnesScriptFx { float uTime; float uSize; float uP0; float uP1; float uP2; float uP3; float uPad0; float uPad1; }` and blend premultiplied: `vec4(rgb * a, a)` overlays, `vec4(rgb, 0.0)` adds light, `a = 1.0` replaces. Chams shade the entity model geometry (seen through walls, only the front layer): inputs `in vec4 vertexColor` (the tint), `in vec2 texCoord0`, `in vec3 viewPos`, `in vec3 viewNormal`, `in vec3 localPos` (position relative to the entity's feet — patterns stick to the entity); `Sampler0` is the model texture (discard where `.a < 0.1`), `Sampler1` is the world behind the model — sample it at `gl_FragCoord.xy / vec2(textureSize(Sampler1, 0))`, the frame is copied only if the shader declares it — and `Sampler3` a tiling noise texture. The vanilla model is hidden while your chams draw, `model: true` keeps it under them. Glow is a fullscreen pass over the entities' silhouettes: inputs `in vec2 texCoord0`, `in vec4 tint`; `Sampler0.r` is the silhouette coverage blurred by `radius` pixels (number or `(e) → number`, default 4, also in `uSize`), `Sampler1` the sharp silhouette (`.rgb` model colors, `.a` coverage), `Sampler2` the current frame (copied only if declared) — all three sampled at `texCoord0`; the classic outer glow is `clamp(blurred - sharp, 0, 1)`. Compile errors go to the script console on the first frame; editing a `.fsh` reloads the script. Keep uniform blocks free of comments (VulkanMod's converter rejects them). The handle has `name`, the setting factories and `remove()`.
Built-in nametag: `esp.nametag.segment("id", {text, color, icon, iconColor, iconAfter, categories, enabled})` appends a segment to the client's nametag (a toggle with this id appears in the Nametag's Elements list). `text`/`color`/`iconColor` are values or functions `(e) → value`; `text` returning null hides the segment for that entity, an empty string leaves only the icon. For your own drawing pass `{width, draw}` instead: `width(e)` returns the width in pixels, `draw(e)` draws at `e.x, e.y, e.w, e.h`. `esp.nametag.background(fn)` replaces the nametag plate: `fn(e)` gets `e.x, e.y, e.w, e.h, e.alpha, e.friend, e.entity, e.category` and draws shapes (`render.rect/gradientH/gradientV/outline/shadow` — it runs in the shape pass, text and images drawn here end up under the plates); return `false` to fall back to the default plate, `background(null)` removes yours. Everything is removed when the script is disabled, reloaded or unloaded.

Client icon names (for `render.icon`, `category.icon`, `watermark.chip`, `esp.element`, `esp.nametag.segment`; case-insensitive, `watermark.icons()` returns them): shield, main, cross, run, user, eye, package, piggy_bank, palette, layout_dashboard, keyboard, plus, refresh, settings, device_floppy, info_circle, trash, chevron_right, caret_right, check, clock_hour_4, search, pill, face_smile, toggle_left, toggle_right, toggle_on, hand_pointer, users, globe, microchip, memory, display, gauge, location_crosshairs, signal, server, network_wired, heart, drumstick, droplet, bolt, copy, dice, close, link, cloud_download, cloud_upload, download, sort, sort_asc, sort_desc, sort_alpha_down, sort_alpha_up, filter, mountain_sun, flame, dragon, flag, circle_nodes, skull, play, pause, skip_next, skip_previous, volume_high, volume_low, volume_mute, music, bug, warning, circle_check, circle_xmark, star, bookmark, object_group, folder, rectangle_list, id_card, crown, language, sun, lightbulb, maximize, wand_sparkles, font, moon, percent, chart_line, chart_simple, square_root_variable, tower_broadcast, link_slash, cloud, satellite_dish, location_dot, user_plus, user_minus, user_slash, thumbtack, swords, code, cart_shopping, clone, crosshairs, parachute_box, altar, skull_crossbones, beacon, tower, box_open, geyser, meteor, meteor_rain, dungeon, gift, volcano, vote, truck, boxes, cube, ship, digging, flower, ghost, envelope, user_group, people_group, ellipsis

Custom UI: `feature.panel({render, click, release, drag, scroll, key, char, open, close})` replaces the module's settings panel in ClickGui with your own (the gear of the module row opens it; the handle has `open()/close()/isOpen()`, `open()` also opens ClickGui). `Screen({...same callbacks, pause, escClose})` creates a standalone screen like the client's ClickGui (`open()/close()/toggle()/isOpen()`). `render(ui)` gets `{x, y, w, h, mouseX, mouseY, alpha, partial}` and draws with `render.*` and setting handles (`setting.render(x, y, w, ui.alpha)`); input callbacks get `{x, y, button, dx, dy}` (click/release/drag), `{x, y, vertical, horizontal}` (scroll), `{key, scanCode, modifiers, press}` (key), `{char, code, modifiers}` (char) and return true to consume. A click outside the panel or ESC closes it; ESC closes the screen unless `escClose: false`. Both close by themselves when the script is disabled, fails or hot-reloads.

Client modules for your own menus: `client.categories()` → `[{name, icon, description, modules()}]` (icon is a name for `render.icon`); a module handle (`client.module(name)` or `category.modules()`) has `name, category, subcategory, description(), enabled(), toggle(), setEnabled(b), hasSettings(), settings()`. Setting handles (both your own and the client's) share one shape: `name, type, get()/set(v)` plus type extras (`toggle`, `is`, `options()`, `enabled(name)`, `isKey`, `children()`, `min/max/step`), drawing `render(x, y, w[, alpha, deferOverlay])` → row height, `overlay()`, `overlayOpen()`, and input `click/release(x, y, button)`, `drag()`, `key(key, scanCode, mods)`, `char(code, mods)`. `render.toggle(x, y, w, h, t[, alpha])` draws the client's switch. The `clickgui` preset is a complete module menu built on these.

Rotation and world actions (legit building, breaking, clicking): `rotation.set(yaw, pitch, opts)` / `rotation.lookAt(x, y, z, opts)` turn the head for the server through the client's own rotation engine (mouse-step rounding, movement correction and a smooth return to the camera are built in). Call them in `events.pre_update` every tick while needed — that is where built-in modules rotate, before the click and the movement packet. `opts`: `speed` (yaw degrees per tick, 180), `pitchSpeed`, `returnSpeed` (12), `pitchReturnSpeed`, `timeout` (ticks to hold without new calls, 1), `priority` (3; the aura uses 4–5 and wins). `rotation.server()` is what the server sees, `rotation.camera()` is where the player looks, `rotation.stop()` returns smoothly (only your own rotation). `world.placeTarget(x, y, z)` finds a support for a new block (neighbour + face + click point, the same shape as a raycast hit), `world.raycast()` casts the server rotation (or `raycast(yaw, pitch, range)`), and `player.place(hit)` clicks exactly like right mouse button. Place only when `world.raycast()` hits the support face — then the click matches the rotation the server received. `player.breakBlock(x, y, z)` is called every tick like a held left button, `player.attack(entity)` / `player.interact(entity)` hit or right-click an entity; all actions return `false` when out of reach and are sent before this tick's movement packet no matter which event calls them. `input.press("jump" | "sneak" | "use" | "attack" | ..., ticks)` presses a game key for the player (the game handles it as a real key). `player.predict(ticks)` simulates the player's movement with the current input. The `scaffold` preset is a complete bridge-builder on these calls.

Combat modules as scripts (presets `autosoup`, `autouse`, `wtap`, `sneaktap`, `uppercuts` are complete examples): `Module("Name", true)` starts the sub-module enabled until the user turns it off, so `pack.feature(...)` shows up in ClickGui right after the script is enabled; `feature.description("feature.impl.combat.autosoup")` and setting names like `"autosoup.health"` are client lang keys and get translated (mode/multi options as `name.option`); `client.lang(key[, fallback])` reads a client string; `client.warn(text, {effect: "minecraft:invisibility"})` / `{item: id}` puts an effect or item icon on the toast; `feature.slider(name, def, min, max, step, "ms")` shows a unit; `multi.set(["a", "b"])` selects options. Item actions: `player.interactItem([hand])` uses the held item like a right click in the air (the client eats/drinks/throws right away), `player.rightClick()` is the full vanilla right click (entity/block under the crosshair, then the item) and works with a screen open, `player.dropHeld([whole])` drops the held item like Q, `player.slot(n)` tells the server immediately. `player.inventory.swapHand(slot[, "main" | "off"])` swaps a screen slot with a hand the way built-in modules do (waits for the input stop while moving, so check the hand in later ticks), `player.inventory.busy()` is true while such a swap is pending. `input.hold(name[, ticks])` holds a key without a click (call every tick, `release` at the end). Item handles have `nutrition`/`saturation` for food and `effects` for potions; entities have `isLiving()`. Aura hooks: `aura.rangeHook(fn)` — `fn({source: "aura" | "trigger", range})` returns a number to replace the attack range of AttackAura / TriggerBot; `aura.hitMomentHook(fn)` — `fn({canCrit, noRoomToJump})` returns `true` to hit now, `false` to skip waiting for a crit (other checks still apply), nothing to keep the built-in crit logic. `aura.track(entity)` reports the script's own combat target so the client's target ESP and TargetHud show it (call every tick while the target is active; no argument clears it).

Movement modules as scripts (presets `nulls`, `jesus`, `fastladder`, `elytrabooster`, `elytrafly`, `nofall`, `autododge`, `highjump`): handlers take a priority among the client modules — `events.move_input(fn, "low")` or `events.on(name, fn, "low")` (`highest`, `high`, `normal`, `low`, `lowest`, only for client bus events); `e.steer(x, z)` in `move_input` turns the input toward a world direction and `move.escapeFrom(entity)` returns `{x, z}` to run away along free ground or null; events `slime_bounce` (cancel = land on slime without bouncing) and `keep_sprint` stage `"legacy"` (cancel = old protocols do not drop the sprint in water/while using items); `multi(name, options, enabledByDefault)`; `input.physical(name)` — physical state of a game key; `entity.prevPos()` — last tick position; `player.age()`, `player.movementInput()` (`{forward, strafe, jump, sneak, sprint}` after all modules), `player.setOnGround(b)`, `player.startGliding()`; `move.jump(true)` jumps in the air, `move.holdJump(ms)` holds jump (client throws wait); `world.bottomY()`, `world.raycast(yaw, pitch, range, "source")` stops only at fluid sources; `player.inventory.findServerItem("plast")` → screen slot of a server item or -1, `player.inventory.throwItem(slot[, yaw, pitch])` throws/uses it like built-in modules, `player.inventory.throwing()`; item handles have `onCooldown`. `aura.hitMomentHook`: `true` from any hook wins, otherwise `false` from any hook.

Holes (low ground): `world.holes([radius = 8])` → `[{x, y, z}]` — floor cells of pits around the player that lie below the surrounding ground: a pit is a patch of floor of any shape (up to 48 cells per level) with no way to walk off sideways — it is bounded by walls that have higher ground or another pit behind them, and a step down only leads into a deeper part of the same pit, so a multi-level crater counts as a whole; a cell merely walled in by placed blocks on flat ground is not a hole. Each cell is standable (free feet and head, no fluid or fire). It is the same definition AutoCrystal uses to pick its spot. It scans a cube of `radius` (1..16), so cache the result by `Timer` instead of calling it every frame.

Threads: every script handler runs on the game's main thread. Incoming packets reach `events.packet` right before the game applies them (cancel drops the packet; bundles are unpacked into separate packets); packets the game handles directly on the network thread (keep-alive, ping) are not delivered. `block_update` arrives for block changes only, not for chunk loading — use `world.findBlocks` for that. `e.data()` in `events.packet` returns the packet's fields (positions, entity ids, slots, texts…) or `undefined` for packets without parsed fields; `e.name` is the protocol id (`move_player_pos`, `set_entity_motion`, `system_chat`…), the same in development and release builds.

Console: `print(...)` and `console.log/info/warn/error(...)` write to the script console (the list icon on the scripts page opens the common console, "Console" in a script card menu or the icon in the editor title opens that script's own console); objects and arrays are printed as JSON, `console.error` marks the line red without stopping the script. Script failures (with the line number) land there too. The console has an input line: in a script's console the code runs in that script's scope (its variables and functions are visible), in the common console — in a separate environment with the whole API; compiled `.ss` scripts accept no input.

Other: `client.say(text)` / `client.command(cmd)` send to the server, `client.isFriend(name)` / `client.friends()` read the friend list, `container.slots()` lists the open container (slot index for `player.inventory.click`), `module.setting(id)` finds a client setting by its stable `id` (the `name` of a setting is translated and changes with the client language).

## Events

Subscribe with `events.<name>(fn)` or `events.on(name, fn)`. The handler gets one argument `e` with the fields listed below (setters change the event); events marked *cancellable* are cancelled by `e.cancel()` or a truthy return. Background hooks (`*_bg`) draw with `render.*`: return `false` to let the client draw its default.
